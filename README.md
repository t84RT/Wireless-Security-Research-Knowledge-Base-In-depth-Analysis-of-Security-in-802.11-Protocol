## 📖 项目简介

本项目是一套 **完整的无线安全研究知识库与实验平台**，系统性地整理和分析了 802.11 协议族的安全架构、管理帧漏洞及纵深防御策略。内容涵盖：

- **802.11 管理帧体系深度解析**（Beacon / Probe / Auth / Assoc / Deauth / Disassoc）
- **Deauthentication / Disassociation 攻击的协议原理、帧结构、代码实现与工具实战**
- **PMF（802.11w 受保护管理帧）的密码学防护机制与部署策略**
- **WPA/WPA2/WPA3 认证与加密体系全链路对比**
- **无线安全研究全景知识树（309 个知识点，12 大章节）**
- **ESP8266/ESP32 嵌入式平台上的完整实现代码**

> ⚠️ **重要声明**：本仓库的全部内容 **仅限用于学术研究、防御性教学和已获书面授权的网络安全测试**。根据《中华人民共和国网络安全法》第二十七条及《中华人民共和国无线电管理条例》，**任何未经授权的无线信号干扰、管理帧注入或网络攻击行为均属违法**。使用者须严格遵守当地法律法规，并承担一切由此引发的法律责任。**禁止**将本仓库的任何内容或代码用于干扰公共或私人通信服务。

## 📚 知识库内容结构

### 第一部分：802.11 协议栈基础

| 章节 | 核心知识点 |
|------|-----------|
| **帧类型体系** | 管理帧(00) / 控制帧(01) / 数据帧(10) 分类与 Frame Control 字段详解 |
| **管理帧深度** | Beacon / Probe / Auth / Assoc / Reassoc / Deauth / Disassoc / Action 全解析 |
| **连接状态机** | State 1（未认证）→ State 2（已认证）→ State 3（已关联）状态跳转逻辑 |
| **Deauth 帧结构** | 26 字节完整剖析：Frame Control / Duration / 地址字段 / Reason Code |
| **Reason Code 大全** | 0x01~0x09 完整对照表，包含攻击最常利用的 Code 1/3/4/7 |

### 第二部分：认证与加密体系演进

| 阶段 | 标准 | 核心机制 | 已知弱点 |
|------|------|----------|----------|
| 历史 | WEP | RC4 + 24-bit IV | IV 复用 → FMS/PTW 统计破解 |
| 过渡 | WPA | TKIP (RC4 + 动态密钥) | Michael MIC 弱点 / Beck-Tews 攻击 |
| 当前主流 | WPA2 (802.11i) | CCMP (AES-128) / 4-Way Handshake | KRACK / 弱 PSK 字典攻击 |
| 现代标准 | **WPA3** | **SAE (Dragonfly)** / **PMF 强制** | Dragonblood（已修复） |

### 第三部分：PMF / 802.11w 受保护管理帧（核心防御）

```
传统 Deauth：明文发送，无认证 → 任何人均可伪造
    ↓
802.11w (PMF)：加密 + MIC 校验 → 无密钥无法伪造
    ↓
防护机制：
├── 单播健壮管理帧 → PTK + CCMP 加密
├── 广播健壮管理帧 → IGTK + BIP (AES-CMAC) 签名
└── SA Query 机制 → 收到未保护 Deauth 时先验证 AP 存活
```

**PMF 两种模式**：
- `Optional`（可选）：兼容旧设备，但攻击面仍存在
- `Required`（强制）：仅允许支持 802.11w 的客户端连接 —— **推荐企业级配置**

### 第四部分：攻击技术与防御工程

| 攻击技术 | 原理 | 防御方案 |
|----------|------|----------|
| **Deauth 泛洪** | 伪造 AP → 客户端 Deauth 帧 | 启用 PMF Required |
| **广播 Deauth** | FF:FF:FF:FF:FF:FF 目标 | PMF BIP 保护组播管理帧 |
| **Handshake 捕获** | Deauth 强制重连 → 抓取 EAPOL | PMF + WPA3 阻止降级 |
| **Evil Twin** | 同名 AP + Deauth 驱离 | WIDS 检测 + 证书绑定 |
| **Karma 攻击** | 响应所有 Probe Request | 客户端 MAC 随机化 + PNL 混淆 |
| **Beacon 泛洪** | 数千虚假 SSID 轰炸 | WIDS 异常 Beacon 检测 |

## 💻 嵌入式实现（ESP8266 / ESP32）

本仓库包含完整的 **ESP8266 Deauther + Beacon 广告机 + Web 管理界面** 实现代码：

### 功能模块
- **WiFi 扫描模块** (`wifi_scanner.cpp/.h`)：AP/STA 扫描、混杂模式回调、RSSI 采集
- **Deauth 攻击模块** (`deauth_attack.cpp/.h`)：Deauth/Disassoc 帧构造、原始帧注入、批量攻击调度
- **Beacon 广告机模块** (`beacon_spam.cpp/.h`)：Beacon 帧伪造、SSID 列表管理、周期性广播
- **Web 管理界面** (`web_server.cpp/.h`)：现代化响应式 Web UI（纯 HTML/CSS/JS）、RESTful API
- **配置与工具** (`config.h/.cpp`)：系统参数、MAC 地址工具、OUI 厂商识别

### 关键技术点
- 原始 802.11 帧注入：`wifi_send_pkt_freedom()` / `esp_wifi_80211_tx()`
- 无网络关联即可发送管理帧
- 硬件 MAC 地址随机化与伪造
- 全信道跳变扫描与攻击

## 🚀 快速开始

### 硬件要求
- **ESP8266 开发板**（推荐 NodeMCU v2 / Wemos D1 mini）
- 支持 **Monitor Mode + 包注入** 的无线网卡（用于外部监听/测试）

### 软件环境
- **PlatformIO**（推荐）或 Arduino IDE
- 依赖库：`ESPAsyncWebServer`、`ESPAsyncTCP`

### 编译与烧录（PlatformIO）
```bash
# 1. 克隆仓库
git clone https://github.com/yourusername/wireless-security-research.git
cd wireless-security-research

# 2. 选择目标板 (platformio.ini 中修改 board)
[env:esp12e]
board = nodemcuv2

# 3. 编译并上传
pio run -t upload

# 4. 串口监视
pio device monitor -b 115200
```

### 使用流程
1. 上电后 ESP8266 创建名为 `Deauther-AP` 的开放热点（密码：`deauther123`）
2. 手机/电脑连接该热点，浏览器访问 `http://192.168.4.1`
3. 通过 Web 界面：扫描目标 → 添加到 Deauth 列表 → 启动攻击
4. **严格在已获授权的实验环境中使用**
